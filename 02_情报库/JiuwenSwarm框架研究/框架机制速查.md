# JiuwenSwarm 框架研究（开发必读）

> 本文件是开发时的框架速查。源码在 `03_技术实现/jiuwenswarm/`（0.2.4.beta4）。
> 详细文档见 `jiuwenswarm/docs/zh/`（40+ 篇）。更新日期：2026-08-11

---

## 1. 核心哲学：Agent = Model + Harness

- **Model**：提供推理（可换，支持 OpenAI 兼容多模型 → 我们配 DeepSeek）
- **Harness**：提供工程控制层——任务循环/工具/上下文/权限/记忆/验证/停止条件/反馈
- **对我们的意义**：我们的 rail 改造在 Harness 层，**与模型解耦**——换 DeepSeek/换旗舰模型，rail 逻辑不变

## 2. Rail 机制（我们的主战场）

**定义**：生命周期扩展面，是"修改 JiuwenSwarm 源码"的主要抓手。

**9 个钩子**：
- 前置：`before_invoke` / `before_task_iteration` / `before_model_call` / `before_tool_call`
- 后置：`after_model_call` / `after_tool_call` / `after_task_iteration` / `after_invoke`
- 异常：`on_*_exception`

**关键能力**：按 priority 排序执行；**可改写 tool_result**（校验/修正数据的能力）；可返回引导性输出。

**内置 rail 家族**（可参照/可继承）：
| 家族 | 成员 | 用途 |
|---|---|---|
| 执行控制 | TaskPlanning / TaskCompletion / AgentMode | 任务循环纪律 |
| 安全权限 | SafetyPrompt / PermissionInterrupt / Verification | 权限治理 |
| 上下文记忆 | ContextAssemble / ContextProcessor / Memory / CodingMemory | 上下文管理 |
| 技能演进 | SkillUse / Evolution / SkillCreate | 技能生命周期 |
| 子代理 | Subagent / VerificationContract | 子任务 |

**实现范式参考**（真实代码）：
- `jiuwenswarm/agents/harness/code/rails/code_plan_approval_rail.py`（状态机 + pending 生命周期）
- `jiuwenswarm/agents/harness/code/rails/code_task_planning_rail.py`（todo 注入 + 生命周期）
- `jiuwenswarm/agents/harness/common/rails/project_memory_rail.py`（挂载 harness 生命周期的通用示例）

## 3. 我们的 rail 挂载位置（规划）

- 新增 rail 文件放：`jiuwenswarm/agents/harness/code/rails/`（或 `common/rails/`）
- 注册方式：`agents/swarm/providers/builtin_rails.py` / `code_rails.py`（声明式装配）或 config
- 依赖：rail 基类在 openjiuwen（agent-core，git 依赖）→ 本地开发需先 `pip install` 依赖

## 4. Auto Harness（自演进底座，D04/T03 用）

- 位置：`agents/harness/common/auto_harness/service.py`（2600+ 行）+ `openjiuwen.rsi.auto_harness`
- 两条 pipeline：
  - **Meta Evolve**（基座层优化）：调研→评估→计划→独立 worktree 实现→CI 验证→PR
  - **Expert Evolve**（领域扩展包）：生成 Package→热加载即插即用
- 触发：`--pipeline optimize_meta_harness` / `optimize_expert_harness`
- 配套：`scheduler.py`（定时）、`task_store.py`（持久化）、`issue_fix/`（GitCode issue 驱动修复）
- 前置条件：GitCode 仓库认证（`repo_auth/gitcode.py`）

## 5. Skill 机制（D01 用）

- 位置：`resources/agent/workspace/skills/`（21 个内置 skill 可参照）
- 结构：SKILL.md（name/description/trigger/allowed_tools/tags）+ references/ + scripts/
- 渐进式披露：按需加载 references/scripts，控制上下文
- 参照模板：`skill-omni-creation`（全能创作）、`doc-update`（文档生成）、`ppt-creation`（含论文原图管线）
- **注意**：框架目前**没有**任何科研/论文写作 skill → 这是我们的空白机会

## 6. Team Skill（D02 用）

- 规范：SKILL.md + roles/ + workflow.md + bind.md + dependencies.yaml
- 配置示例：`resources/config.team.distributed.leader.yaml` / `teammate.yaml`
- 团队代码：`agents/team/`（leader/teammate、a2x 协议）

## 7. 权限与安全（别踩坑）

- `docs/zh/工具权限与安全防护.md`：PermissionEngine（allow/ask/deny）+ AST 命令分析 + HITL
- 我们的 rail 若拦截/改写结果，注意与权限 rail 的 priority 配合（别冲突）
- `code/rails/code_agent_mode_rail.py`：plan 模式下拦截非 git 写操作——**参照它做"实验阶段禁写论文"之类的模式管控**

## 8. 环境与依赖（阶段 0 用）

- Python `>=3.11,<3.14`
- 核心依赖：`openjiuwen[claude,codex] @ git+https://gitcode.com/openJiuwen/agent-core.git@develop`
- 其他：chromadb/faiss/sqlite-vec（向量存储）、fastapi/uvicorn（服务）、loguru/pydantic
- 入口：`jiuwenswarm` → `jiuwenswarm.cli.main:main`
- 快速上手：`docs/zh/Quickstart.md`
- 测试：`tests/`（pytest，rail 有现成单测范式可参照）
