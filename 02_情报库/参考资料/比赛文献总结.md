## 2. 评分体系拆解

### 2.1 Stanford Agentic Reviewer（SAR）—— 初赛自动化打分

- 斯坦福吴恩达团队主导，模拟顶会（ICLR/NeurIPS/ICML）审稿流程的 AI 审稿 Agent
- 基于 ICLR 2025 审稿数据训练 + arXiv 检索 + 结构化评审，与人类审稿相关性 0.42（人类间 0.41）
- 官方入口：https://paperreview.ai

### 2.2 六大评审维度（大赛直接评分依据）

| 维度 | 权重（折40分） | 核心评估要点 |
|---|---|---|
| 1. 研究重要性 | 20%（8分） | 问题价值、领域贡献、应用前景 |
| 2. **原创性/创新性** | **25%（10分）** | 与现有工作差异、新方法/新视角、技术突破 |
| 3. 方法合理性 | 20%（8分） | 技术方案可行性、逻辑严谨性、实现细节 |
| 4. 实验严谨性 | 15%（6分） | 实验设计、数据支撑、结果可复现、ablation |
| 5. 写作清晰度 | 10%（4分） | 结构完整性、表达流畅性、图表规范、引用合规 |
| 6. 相关工作完整性 | 10%（4分） | 文献覆盖度、对比充分性、研究定位清晰 |

> **注**：SAR 原始总分（0-10）×4 = 自动化打分（40 分）

## 3. 核心文献 #1

### 《How Far Are We From True Auto-Research?》（"我们离真正的自动科研还有多远？"）

- **作者**：Zhengxin Zhang, Ning Wang, Sainyam Galhotra, Claire Cardie（Cornell University）
- **arXiv**：2605.19156v1 [cs.AI]，2026-05-18
- **全文已存本地**：`fars_paper_text.txt`（100k 字符，含附录 A-I 完整内容）

### 3.1 研究内容

让 3 个现成 agent（Claude Code/Opus 4.6、Codex/GPT-5.4、Kimi Code/K2.5）在**最小引导（lightweight guidance）**下自主跑完整科研循环（ideation→experiments→paper writing→review，前三阶段各带 self-refinement），产出 **117 篇论文**，用三种方式评测，并与 FARS 和 200 篇人类 ICLR 2025 论文对照。

### 3.2 关键数据

**SAR 分数对比表（论文 Table 1）：**

| 系统 | n | 均值 | σ | 单篇成本 | 过审率* |
|---|---|---|---|---|---|
| ICLR 录用（人类） | 100 | 5.59 | 0.59 | — | — |
| ICLR 加权（人类） | 200 | 5.42 | 0.70 | — | — |
| ICLR 拒稿（人类） | 100 | 5.34 | 0.75 | — | — |
| **Claude Code** | 39 | **5.45** | 0.70 | ~$9 | **21%** |
| **FARS（Analemma）** | 102 | **5.06** | 0.62 | **~$1,040** | **1%** |
| Codex | 39 | 4.93 | 0.85 | ~$9 | 10% |
| Kimi Code | 39 | 4.24 | 0.84 | ~$9 | 0% |

*过审率 = SAR 评分越过录用阈值（≈5.5+）的论文占比。FARS 仅 1/102（1%），Claude Code 8/39（21%）。

**三大核心发现：**

1. **FARS 不是天花板**：最小 scaffold + 现成 agent（~$9/篇）超过重工程化闭源系统（~$1,040/篇），**便宜 100 倍且分数更高**。
2. **SAR 不可单独信任**（§5.1）：
   - 人类评审录用 vs 拒稿分数差 1.52（6.54 vs 5.02），SAR 只压缩到 0.25（5.59 vs 5.34）——SAR 区分度远弱
   - SAR "奖励合理表述，不核实实验实质"（rewards plausible framing without verifying experimental substance）
   - SAR 接受率：人类录用论文 76%、人类拒稿 52%、Claude 41%、FARS 22%、Codex 13%、Kimi 5%
3. **实验严谨性是最大瓶颈**（§5.2），三大失败模式（全部 agent 平均）：
   - **捏造结果**（fabricated results）：报告数字与 results.json 不符、代码未实现的组件论文声称有、假引用。Codex 5%/8% vs Kimi Code 77%/72%（~15 倍差距）
   - **实验支撑不足**（underpowered）：49.6%——单数据集当多个用、单 seed、明确写成 pilot/feasibility
   - **计划与执行不匹配**（plan/execution mismatch）：23.9%——计划里的 baseline 代码里没有、ablation 没跑
   - 通病：拿旧 baseline 对比，即使相关工作提到新 baseline 也不用

### 3.3 研究人格分析（§4.2）——SAR 高分特征配方

| 信号 | Claude Code（高分） | Codex | Kimi Code（低分） |
|---|---|---|---|
| 论文长度 | 4,023 词 | 3,421 词 | 2,461 词 |
| 图/表 | 4.8 / 6.0 | 4.1 / 4.2 | **0.8 / 4.0** |
| 含复杂度分析 | **77%** | 10% | 64% |
| 研究类型 | 方法46%+实证46% | 实证87% | 方法79% |
| 实验时长 | 13.0h | 6.8h | 4.1h |
| 失败特征 | 偶发局部捏造 31% | 最诚实 5% 但保守 | 全面捏造 77%、82% underpowered |

**结论**：长论文 + 多图表 + 复杂度分析 + 诚实实验 + 充分实验时长 = SAR 高分画像。

### 3.4 其他要点

- **算力不是瓶颈**（§5.4）：8×H100 重跑 GPU seeds，Codex PR 从 4.51 降到 4.26——"限制因素是 agent 的实验设计能力，不是算力"
- **负结果加分**：PR 和 SAR 都给"诚实报告负结果"加分（人类评审不会）
- **结论**：117 篇无一达到顶会录用标准，自动科研仍与真正研究有差距
- **未来方向（§6）**：① 自动评审需要人类校准 ② 端到端忠实性训练 ③ **"需要更强的实验规划 scaffold"——这正是 Rail 增强的空白**

### 3.5 附录 B：四阶段完整指南（可直接复用的操作手册）

论文附录 B 附上了让 agent 跑科研流程的**完整 prompt 原文**，已提取到本地文本中：

- **Ideation 指南**：选题方法论（Schulman 建议）、novelty 三步验证、proposal.md / idea.json / references/ 结构
- **Plan 指南**：plan.json 格式（7 类实验类型表）、公平 baseline 规则（≥2 个）、ablation 前置规划、**运行时预算估算公式**、Plan Quality Checklist
- **Experiment 指南**：并行调度模式（CUDA_VISIBLE_DEVICES）、workspace 结构（每实验独立文件夹+config+results.json+logs）、复现性清单
- **Writing 指南**：写作顺序（先方法→实验→贡献→结论，摘要最后写）、**论文数字必须与 results.json 逐字一致、明令禁止捏造**

## 4. 核心文献 #2

### Analemma FARS（Fully Automated Research System）官方资料

- **官网**：https://analemma.ai/（公司 Analemma Intelligence）
- **博客**：https://analemma.ai/blog/introducing-fars/
- **状态**：闭源，GitHub 组织无公开仓库；代码与论文均未公开

### 4.1 已知架构事实（官方博客 + 比赛页面）

1. **四模块流水线**：Ideation（文献调研/假设生成）→ Planning（实验方案设计）→ Experiment（代码编写/执行/收集）→ Writing（论文撰写/图表生成），"科研装配线"
2. **模块间靠共享文件系统协作**："All agents collaborate through a shared file system, which serves simultaneously as a workspace and a persistent memory"——agent 不直接通信，读写项目目录完成衔接，可并行多个项目
3. **Ideation 输入**：指定多个研究方向的文档；**每个假设须先通过 automated review 才能进下游**
4. **实验环境**：160 张 NVIDIA GPU 集群 + 模型推理端点，可调度数据合成、agent 设计、LLM-as-a-Judge 实验
5. **人工审查**：论文提交 arXiv 前须经 ≥3 位 5 年以上经验研究员审查，并标注 AI 生成——"无人值守"指生成过程，非全程无人把关
6. **阴性结果策略**：假设有充分动机即可报告，无论正负，减少发表偏差

### 4.2 已披露运行数据（比赛页面）

- 228 小时 28 分连续公开运行，产出 **244 个有效假设、100 篇 AI 领域短论文**（~2h17m/篇）
- 消耗 **114 亿 Token，总成本 $104,000（约 $1,040/篇）**
- SAR 均分 **5.05**（ICLR 2026 人类平均 4.21，人类中稿 5.39）
- 能力：全流程无人值守、快速跟进新成果（GG-SM 发布 3 天接入）、自动设计基线/主/对比/消融实验、负结果诚实呈现、引文无明显幻觉

### 4.3 FARS 被点名的四大局限（= 参赛优化方向）

1. **算力利用率低**：1.14 亿 Token/篇（普通写作百万级），"算力换智能"
2. **研究创新性不足**：工程优化/现有方法改进为主，难达顶会录用
3. **机制洞察深度欠缺**：结果分析表面化，原因解释不充分
4. **复杂假设筛选能力弱**：能生成大量假设，但筛选高价值复杂假设能力不足

### 4.4 相关评测结论（交叉验证）

- ResearchArena 论文评测 FARS：SAR 5.06、过审率仅 1%、单篇成本 $1,040——**重资产 ≠ 高质量**

### 5.1 JiuwenSwarm 核心机制速记

- **公式**：`Agent = Model + Harness`——模型提供推理，Harness 提供工程控制层（任务循环/工具/上下文/权限/记忆/验证/停止条件/反馈）
- **Rail**：生命周期扩展面，9 个钩子（before_invoke / before_task_iteration / before_model_call / before_tool_call / after_* / on_*_exception），按 priority 排序，可改写工具结果
- **内置 rail 家族**：执行控制（TaskPlanning/TaskCompletion/AgentMode）、安全权限（SafetyPrompt/PermissionInterrupt/Verification）、上下文记忆（ContextAssemble/ContextProcessor/Memory/CodingMemory）、技能演进（SkillUse/Evolution/SkillCreate）、子代理（Subagent/VerificationContract）
- **Auto Harness**：评测→找差距→worktree 实现→验证→热加载（Expert）或提 PR（Meta）
- **权限治理**：PermissionEngine（allow/ask/deny）+ AST 命令分析 + HITL 确认
- **内置子代理**：browser_agent / code_agent / research_agent / verification_agent / mobile_gui_agent

### 5.2 概念澄清：Auto Harness 的"后训练"

- **后训练（post-training）** 本义：LLM 预训练后的所有训练（SFT/RLHF/RLVR），**改模型权重**
- **Auto Harness 借用类比**：把"调教 Agent 行为"自动化——Agent 分析自身 Harness 不足、生成改进方案、实现并验证，**改的是 prompt/工具/rail/skill，不改权重**
- 对应关系：预训练=Harness 出厂配置；后训练=改 Harness；RLHF=评测驱动闭环

## 6. 情报要点汇总

1. **FARS 可被超越**：SAR 5.06 / $1,040 每篇 vs 最小 scaffold 5.45 / $9 每篇——重资产不是优势
2. **SAR 有表述红利**：奖励合理表述不核实实质；同时区分度弱（0.25 vs 人类 1.52）
3. **图表密度是分数信号**：Claude Code 4.8 图 vs Kimi 0.8 图，SAR 差 1.2 分
4. **实验严谨性是全场通病**：三大失败模式平均中招率 25%-50%，做到"数字与 artifact 一致"即差异化
5. **算力不是瓶颈**：H100 反而降分（4.51→4.26），限制因素是实验设计能力
6. **负结果在 SAR 眼里是加分项**（人类评审不这么看）
7. **引用真实性直接决定相关工作维度**：Codex 假引用 8% vs Kimi 72%
8. **模型可换、Harness 是护城河**：JiuwenSwarm 支持 OpenAI 兼容多模型，你的 rail/流水线与模型解耦
9. **比赛合规路线 = 论文叙事路线**：改源码提 PR 既是硬性要求又是创新性证据
10. **每日 3 次提交 = 免费 A/B 实验窗口**：SAR 输出 6 维度评分+修改建议，可作自动化反馈循环

## 7. 对参赛方案的关键启示

1. **写作质量配方（决定 SAR 下限）**：≥4000 词、4-5 图 + 6 表、77% 论文含复杂度分析、结构完整、诚实报告负结果——全部可写成 Writing rail 的硬校验
2. **选题 meta 打法（决定创新性 25%）**：论文主题 = 你的真实贡献（如"Rail-Augmented Harness for Rigorous Agentic Research"），创新性/方法合理性/实验严谨性三维度自洽；ResearchArena 论文 §6 明确"需要更强的实验规划 scaffold"——正是 Rail 增强的空白
3. **实验严谨性 rail（决定 15% + 决赛安全垫）**：Plan rail（plan.json 强制：≥2 baseline、ablation 前置、固定 seed、预算估算）→ 结果校验 rail（论文数字=results.json 逐字一致）→ 引用校验 rail（arXiv/Semantic Scholar 在线核验）
4. **成本策略**：DeepSeek 等性价比模型 + 最小 scaffold，目标单篇 $10 量级，放弃 FARS 式重资产路线
5. **Auto Harness 双用途**：Meta pipeline 提的 PR = 框架贡献交付物 + 论文"Harness 自演进"实验证据
6. **防坑清单**：不捏造（决赛复现审核）、不做 pilot 式论文、计划必执行、用新 baseline、负结果如实写
