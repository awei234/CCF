# 评分体系拆解

> 目标：把"SAR 评分"这个黑盒翻译成**可执行的工程动作**。本文件是 01_方向库 各方向优先级排序的依据。
> 更新日期：2026-08-11

---

## 1. 分数构成总览

```
最终成绩 = 初赛三轮最高分 → TOP5 入围决赛 → 决赛评审（复现 + 答辩）

初赛自动化打分（40 分）= Stanford Agentic Reviewer 原始总分(0-10) × 4
论文质量总分 60 分，其中自动化 40 分（2/3），其余 20 分官方未明示
（推测：技术包质量 / 框架贡献 / 资源报告完整度）
```

**核心结论**：SAR 一分 ≈ 折算 4 分。SAR 从 5.0（FARS 水平）提到 5.5（Claude Code 水平），初赛分差 2 分；提到 6.0+，就是领跑位。

## 3. SAR 的行为特征（来自 FARS 评测论文，规避误判的关键）

1. **奖励"合理表述"不核实"实验实质"**：文笔好的论文即使实验弱也能拿分 → 写作质量是**下限保障**，不是可吹嘘项
2. **区分度弱**：人类审稿录用 vs 拒稿差 1.52 分，SAR 只压缩到 0.25 → 六维均衡很重要，单点爆发救不了短板
3. **图表密度强相关**：Claude Code 4.8 图/6.0 表 vs Kimi 0.8 图/4.0 表，分差 1.2 → 图表的"多"和"规范"直接加分
4. **含复杂度分析加分**：高分论文 77% 含复杂度分析（O 分析）→ 每篇论文必须有
5. **负结果在 SAR 眼里是加分项**（人类评审不这么看）→ 诚实报告负结果，反而差异化
6. **过审率参考**：SAR≈5.5+ 视为"过审"，Claude Code 21%、FARS 仅 1%

## 5. 三大"送命"失败模式（SAR 扣分重灾区）

| 失败模式 | 平均中招率 | 防御机制 |
|---|---|---|
| **捏造结果**（数字与 results.json 不符、假组件、假引用） | 最高 77%（Kimi） | F03 结果一致性 Rail + F04 引用校验 Rail |
| **实验支撑不足**（单数据集当多个、单 seed、写成 pilot） | 49.6% | F02 实验严谨性 Rail（强制多 baseline、固定 seed）|
| **计划与执行不匹配**（计划的 baseline 没实现、ablation 没跑） | 23.9% | F02 plan.json 勾稽校验 + 完成度检查 |

## 6. 决赛环节（TOP5 入围后的加分项）

- 决赛综合考察**复现审核 + 答辩评审**（官方未公布细则）
- 复现审核 = 评委按技术包复现你的论文 → 技术包质量 + 结果一致性是决赛生命线
- 提前准备：技术包做成"一键复现"（环境依赖锁死、复现脚本、README）

## 7. 评分 → 策略映射（一页速查）

```
SAR 六维中，用"系统/工程"能直接控制的：
  原创性  ← 论文主题 + 主线选型（Rail scaffold）
  方法    ← rail 实现质量 + 技术文档
  实验    ← F02/F03/F04（我们的核心差异化）
  写作    ← F01 硬校验（词数/图表/结构）
  相关    ← F04 引用核验 + 调研 skill

用"系统/工程"控制不了的：
  重要性  ← 选题（人为决策，一次定）
```

> **一句话策略**：原创性靠选型（一次决定），方法/实验/写作/相关靠系统（rail 全自动），重要性靠叙事（intro 写故事）。系统部分是我们可以 100% 掌握的，是刷分主力。
