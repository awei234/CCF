# 比赛目标

> 本文件定义本次参赛的**目标体系**。所有方向的选择、任务的优先级、资源投入的分配，均以此为准绳。
> 更新日期：2026-08-11

---

## 1. 一句话目标

**用「轻资产 + Rail 增强 Harness + 严谨实验」路线，把「基于 JiuwenSwarm 的 Agent 自动写科研论文」做到 SAR 分数 ≥ 5.5（折算 ≥ 22 分），进 TOP5 决赛，冲击奖项，同时完成合规的源码贡献（PR + 开源）。**

## 2. 目标分层

| 层级 | 目标 | 量化指标 | 依据 |
|---|---|---|---|
| L0 底线 | **作品有效**（合规） | 基于 openJiuwen 开源代码开发；**修改 JiuwenSwarm 源码**；有 PR 链接；代码开源 Atomgit | 硬性要求，不满足 = 无效作品 |

| L3 论文 | SAR 分数达标 | SAR ≥ 5.5（折算 ≥ 22/40）；六维均衡、无短板 | 对标 Claude Code 5.45 / 过审率 21% |
| L4 框架 | 贡献可量化 | 1+ 个 merge 的 PR；新增 rail/skill 文档齐备；Auto Harness 自演进证据 | 框架贡献说明交付物 |

## 3. 分数目标拆解（SAR 六维）

> SAR 原始总分 0–10，×4 = 自动化打分（满分 40，占论文质量 60 分的 2/3）。
> 目标 SAR 5.5+ 对应的六维画像（基于文献中 Claude Code 高分画像）：

| 维度 | 权重 | 目标分 | 达成手段（对应方向） |
|---|---|---|---|
| 研究重要性 | 20% | 5.5 | 选题锚定 Agent 前沿（上下文/记忆/自演进），问题价值明确 |
| 原创性/创新性 | 25% | 5.5 | 主线：Rail 增强 Harness 的科研严谨性 scaffold（FARS 论文 §6 明确空白）|
| 方法合理性 | 20% | 5.5 | 方法=rail 生命周期改造，技术路线清晰可复现 |
| 实验严谨性 | 15% | 5.5 | F02 实验严谨性 Rail + F03 结果一致性 + F04 引用校验（差异化核心）|
| 写作清晰度 | 10% | 6.0 | F01 写作质量 Rail：≥4000 词、4-5 图+6 表、复杂度分析、结构完整 |
| 相关工作完整性 | 10% | 5.5 | 引用真实性校验 + 新 baseline 对比 + 文献覆盖 |

## 6. 不做清单（防止跑偏）

1. **不追 FARS 式重资产**：不上百卡 GPU、不烧 $1,000/篇，目标单篇 $10 量级
2. **不做纯提示词工程**：必须动源码（硬性要求），rail 为主、prompt 为辅
3. **不捏造数据**：决赛有复现审核，实验数字与 results.json 必须一致
4. **不分散**：主线之外的方向只做情报储备，不投入开发
5. **不裸提交**：每次提交前过一遍防坑清单（详见 02_情报库/FARS标杆分析/）
