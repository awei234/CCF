# 复现闭环修改细则

> 本文记录“进阶版完善建议”中 P0 复现闭环的本轮落实情况。  
> 实施范围：无密钥 demo、可移植配置、入口失败码、技术包文档与版本清单。  
> 未包含：真实 v7 模型实验、服务器部署、SAR 新提交、历史密钥轮换。

## 一、修改目标

本轮将技术包从“依赖作者服务器路径和人工复制”的说明型交付，改为可在 Linux/WSL 环境离线验证的最小复现闭环。评审者无需模型 API 或运行服务，即可检查随包的 Rail、Skill、扩展配置与 demo 数据审计链路。

## 三、行为边界

### 1. Demo 不等于真实实验

`code/demo/` 的全部内容均标识为 demo，仅验证以下工程事实：

- 技术包包含 F02/F03/F04、科研 Skill 与扩展注册配置；
- 计划、结果、论文数字和引用索引可形成离线审计链；
- 缺少扩展配置、无来源数字或未登记引用时，审计能返回失败。

它**不**证明 v6/v7 的 SAR 分数、模型效果或跨模型结论。真实实验必须另行归档 `plan.json`、逐 seed `results.json`、rejection/audit log 与预注册协议。

### 2. 三条 Rail 的当前强度

- F02：写入 `plan.json` 前的 hard block；不合规计划会跳过工具调用。
- F03：检测论文数字与结果数据的勾稽关系，并注入修复提示。
- F04：检测 cite key 是否命中本地引用池，并提示进行在线核验。

本轮没有把 F03/F04 改造成 PDF 导出 hard gate；这是下一阶段“发布前 Gate”的独立任务。

## 四、验证记录

新增的标准库测试覆盖了以下行为：

1. 完整 demo 审计生成 `audit_report.json` 并通过；
2. 无来源数字会使审计失败；
3. 缺失 `extensions_config.json` 会使布局检查失败；
4. 实际 Prototype 资源布局完整；
5. 未配置实验脚本返回非零；
6. `demo-audit` 函数与命令行均能写出报告；
7. 从技术包目录外调用命令行仍能定位默认配置。

执行结果：`python -m unittest discover -s 06_提交物/Prototype/code/tests -p 'test_*.py'`，共 8 项通过。

现有 F02/F03/F04 pytest 测试已在 JiuwenSwarm 的隔离环境复验：

```powershell
03_技术实现\jiuwenswarm\.venv\Scripts\python.exe -m pytest -q --no-cov `
  03_技术实现\custom_rails\tests
```

结果：**16 项通过**，耗时 3.47 秒。为规避 GitCode 远程仓库返回大量临时引用造成的依赖同步不稳定，本次将已成功克隆的 `openjiuwen` 源码以无依赖开发模式装入隔离环境；未调用模型 API、未启动服务、未运行 v7。测试输出含 3 条上游依赖弃用警告（Pydantic 配置写法、DashScope Assistants API），均不影响三条 Rail 的测试结果。
