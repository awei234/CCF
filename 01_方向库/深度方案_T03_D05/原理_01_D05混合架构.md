# 原理 01：D05 混合架构（四层系统怎么搭）

> 目标：把「自动科研系统」拆成四层，讲清每一层"是什么、解决什么问题、用什么机制实现"，以及层与层之间数据怎么流动。
> 对应方向：D05 混合架构（= D01 + D03 + D04 + 底座）。

---

## 1. 核心前提：Agent = Model + Harness

JiuwenSwarm 的哲学：**Agent = Model（大脑）+ Harness（身体）**。

- **Model**：LLM 负责思考、生成（我们用 DeepSeek）。
- **Harness**：工程控制层，负责"纪律"——任务循环、工具、上下文、权限、记忆、验证、停止条件、反馈。

**为什么必须先理解它**：我们的整套系统，就是在这两层上分别做文章——

| 层 | 我们做什么 |
|---|---|
| Model 层 | 只做配置（DeepSeek 接入），不改模型 |
| Harness 层 | **全部工作都在这里**：skill（流程）、rail（管控）、Auto Harness（演进） |

> 推论：我们的所有能力（rail/skill）与模型解耦。换 DeepSeek、换旗舰模型，harness 层逻辑不变。这也写进论文的方法论。

## 2. 四层架构总览

```
┌────────────────────────────────────────────────────────────┐
│ 第4层 演进层：Auto Harness（原理_02）                        │
│   —— 让系统越干越好（自评估→自改进→再验证）                 │
│   Expert pipeline → Package 热加载（进化能力）               │
│   Meta pipeline → PR（沉淀贡献，合规交付物）                 │
├────────────────────────────────────────────────────────────┤
│ 第3层 管控层：自定义 rail（原理_03 + 行动_Rail实现规格）      │
│   —— 让系统按规矩干活（规划/校验/拦截，机制保证严谨性）      │
│   F02 实验规划 ｜ F03 结果一致 ｜ F04 引用核验 ｜ F01 写作质量 │
├────────────────────────────────────────────────────────────┤
│ 第2层 流程层：科研 skill（D01）                             │
│   —— 让系统会干活（四阶段流水线：选题→调研→方法→实验→写作→分析）│
├────────────────────────────────────────────────────────────┤
│ 第1层 底座：JiuwenSwarm + DeepSeek                          │
│   —— 能干活（框架基础设施 + 推理能力）                      │
└────────────────────────────────────────────────────────────┘
层间数据契约：workspace/ 下的 plan.json → results.json → paper.tex
```

每一层解决一个问题，越往上越"智能"，越往下越"基础"。**开发顺序从下往上**（阶段 0 底座 → 阶段 1 流程 → 阶段 2 管控 → 阶段 5 演进）。

## 3. 第 1 层：底座（JiuwenSwarm + DeepSeek）

### 3.1 是什么

- JiuwenSwarm：框架，提供一切基础设施（CLI、agent 装配、工具、记忆、频道）。
- DeepSeek：推理模型，通过 OpenAI 兼容接口接入。

### 3.2 关键配置（DeepSeek 接入的真实写法）

来源：`03_技术实现/jiuwenswarm/jiuwenswarm/resources/config.yaml`（235–292 行 `models.defaults`）：

```yaml
models:
  defaults:
    - model_client_config:
        api_base: https://api.deepseek.com      # DeepSeek 官方 OpenAI 兼容端点
        api_key: ${DEEPSEEK_API_KEY}            # 环境变量注入，别写死
        model_name: deepseek-chat               # 或 deepseek-reasoner
        client_provider: OpenAI                 # 走 OpenAI 兼容协议
        timeout: 360                            # 必须 > stream_first_chunk_timeout
        stream_first_chunk_timeout: 300         # reasoning 模型思考期可能静默
        stream_idle_timeout: 120
        verify_ssl: true
      model_config_obj:
        temperature: 0.95
      is_default: true
```

**要点**：
- `client_provider: OpenAI` 是关键——DeepSeek 走 OpenAI 兼容协议，JiuwenSwarm 直接支持。
- 超时参数三个（timeout / stream_first_chunk_timeout / stream_idle_timeout）必须按注释要求配置，否则 reasoning 模型长思考会超时。
- API key 用环境变量，参考 `.env.template`（有 `API_BASE / MODEL_NAME / MODEL_PROVIDER` 变量示例）。

### 3.3 开发与运行入口

- CLI：`jiuwenswarm`（→ `jiuwenswarm.cli.main:main`）
- 快速上手：`jiuwenswarm/docs/zh/Quickstart.md`
- 可选：`D:\download\JiuwenSwarm\` 打包版作为无源码环境的备用

## 4. 第 2 层：流程层（科研 skill）

### 4.1 是什么

一个自定义 **skill**，把论文自动化全流程写进 SKILL.md 与脚本，Agent 按手册执行。这层回答"会干活"。

### 4.2 skill 机制（JiuwenSwarm 规范）

- 结构：`SKILL.md`（frontmatter：`name / description / trigger / allowed_tools / tags`）+ `references/`（渐进式披露的深度资料）+ `scripts/`（可执行脚本）。
- 内置 21 个 skill 可参照（`resources/agent/workspace/skills/`），框架目前**没有**科研/论文类 skill——空白机会。
- 参照模板：`skill-omni-creation`（全能创作）、`doc-update`（文档生成）。

### 4.3 四阶段流水线（skill 的内容来源）

直接改编 FARS 论文附录 B 的完整 prompt（存于 `02_情报库/FARS标杆分析/fars_paper_text.txt`）：

| 阶段 | skill 职责 | 产出物 |
|---|---|---|
| Ideation 选题 | Schulman 选题法 + novelty 三步验证（F05）| `proposal.md` / `idea.json` / `references/` |
| Planning 规划 | plan.json 结构 + 公平 baseline 规则 + 预算公式（F02）| `plan.json` |
| Experiment 实验 | workspace 结构规范（每实验独立目录+config+results.json+logs）| `results.json` |
| Writing 写作 | 写作顺序 + 数字与 results.json 逐字一致 + 禁捏造（F03/F04/F01）| `paper.tex` → PDF |

> skill 是"手册"，rail 是"执法者"。手册告诉 agent 怎么做，rail 强制它必须这么做。二者配合，缺一不可。

## 5. 第 3 层：管控层（自定义 rail）★差异化核心

### 5.1 是什么

修改 JiuwenSwarm 源码，新增自定义 **rail**，在 agent 生命周期关键节点强制校验科研流程。这层回答"按规矩干活"，是官方"进阶思路"（改源码 + rail 拓展 harness），也是比赛硬性要求的满足点。

### 5.2 管控点与对应 rail（详见 行动_Rail实现规格.md）

| rail | 管控时机 | 防什么病（FARS 实测中招率）|
|---|---|---|
| F02 实验规划 | 规划阶段：plan.json 不达标不放行 | 实验支撑不足（49.6%）/ 计划执行不匹配（23.9%）|
| F03 结果一致 | 写作阶段：论文数字必须有 results.json 出处 | 捏造结果（最高 77%）|
| F04 引用核验 | 写作阶段：引用必须在线可查 | 假引用（最高 72%）|
| F01 写作质量 | 写作阶段：词数/图表/复杂度/结构硬校验 | 写作短板（SAR 下限低）|

### 5.3 原理速记（详细见 原理_03）

- 基类：`DeepAgentRail`（`from openjiuwen.harness.rails import DeepAgentRail`）
- 钩子全为 `async (ctx) -> None`，靠**就地修改 ctx** 实现拦截/注入/引导
- priority 数值大先执行；我们选 20–50 区间
- 三大操作：拦截工具（`ctx.extra["_skip_tool"]`）、注入规则段（`system_prompt_builder.add_section`）、强制结束（`request_force_finish`）

## 6. 第 4 层：演进层（Auto Harness）

### 6.1 是什么

让系统"越干越好"——自主评估自身不足 → 设计改进 → 实现 → 验证 → 沉淀。这层是 T03 论文卖点的系统本体（详见 原理_02）。

### 6.2 与前三层的关系

- 演进对象 = 第 2 层（skill）、第 3 层（rail）、底座（prompt/tool）
- 触发方式：系统跑完几轮论文生成后，把 SAR 反馈喂给 Auto Harness → 让它改进 rail/skill → 热加载 → 再生成 → 对比 SAR

---

## 7. 层间数据契约（这是架构的"血管"）

四层之间不靠"喊话"，靠**共享工作区文件**（FARS 也是这么设计的：共享文件系统即工作区即记忆）。协议：

```
workspace/
├── proposal.md              # Ideation 产出（F05 校验对象）
├── idea.json                # 结构化选题（novelty 声明）
├── references/              # 调研文献（→ F04 引用候选池）
├── plan.json                # 实验计划（F02 强制校验）
├── experiments/             # 实验产物区（F02→F03 勾稽）
│   ├── exp1/
│   │   ├── config.json      # 实验配置（种子/baseline/数据源声明）
│   │   ├── results.json     # 实验数据（F03 唯一数据源）
│   │   └── logs/
│   └── exp2/ ...
└── paper/
    ├── paper.tex            # 写作产物（F01/F03/F04 校验对象）
    └── figures/             # 图表（数据来源可追溯）
```

**勾稽链**：`plan.json 声明什么 → experiments/ 必须产出什么 → paper.tex 只能引用 results.json 里的什么`。一条链贯穿四层，保证"计划-执行-报告"一致。

## 8. 一张图看懂"系统一天"（D05 全流程走一遍）

```
1. [第2层] skill 引导：选题拆解 → 文献调研 → 出 proposal.md + idea.json
2. [第3层] F05/F02 把关：idea 没过 novelty 验证？plan.json 缺 baseline？→ 打回重写
3. [第2层] agent 按 plan 跑实验，产 results.json
4. [第3层] F03 勾稽：plan 里的实验都跑了吗？结果文件齐吗？→ 不齐打回
5. [第2层] agent 写 paper.tex
6. [第3层] F03/F04/F01 把关：数字有出处？引用查得到？词数/图表达标？→ 不达打回
7. [输出] paper.tex → PDF → 提交 SAR 评测 → 6 维分数 + 修改建议
8. [第4层] Auto Harness 读 SAR 反馈 → 评估"严谨性 rail 是否够强" →
           design 改进方案 → 热加载新 rail → 回到 1 再跑 → 对比 SAR
9. [第4层] 效果好的改进 → Meta pipeline 提 PR → 框架贡献交付物
```

**注意第 8 步**：这就是 T03 的"自演进闭环"与 SAR 评分的咬合点（详见 原理_02 §6、行动_自演进实验设计 E2）。

## 9. 开发顺序与依赖

```
阶段 0 底座 ──→ 阶段 1 skill（第2层）──→ 阶段 2 rail（第3层）──→ 阶段 5 Auto Harness（第4层）
   │              │                   │                     │
   └─ 环境/模型    └─ 第一篇论文+基线   └─ F02/03/04+第二轮提交 └─ 自演进实验E2+PR
```

- 依赖：上层依赖下层。第 2 层要第 1 层能跑；第 3 层要第 2 层有产物可校验；第 4 层要第 3 层有 rail 可演进。
- **每层都有独立交付物**（skill → 论文 v1；rail → 论文 v2；演进 → 实验数据 + PR），所以任何一层卡住都不影响整体推进。
