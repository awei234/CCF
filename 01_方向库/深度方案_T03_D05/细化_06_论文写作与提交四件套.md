## 1. ICLR 模板获取与自制（阶段 1 就该做，阶段 4 必须完成）

### 1.1 现状

`04_论文写作/` 目前只有占位 README，**没有任何 .tex/.cls/.sty**。全盘搜索确认过。所以模板必须自己拿。

### 1.2 三个获取途径（按推荐顺序）

**途径 1：ICLR 官方 GitHub（推荐，免翻墙风险小）**

```bash
# 本地（Git Bash）或服务器均可
cd /home/vergil/CCF/04_论文写作   # 服务器路径；本地用 D:/download/CCF/04_论文写作
git clone --depth 1 https://github.com/ICLR/Master-Template.git iclr_template
```

- 仓库内有 `iclr2025/`、`iclr2026/` 等子目录，选最新年份
- 需要的文件：`iclr2026.sty`、`iclr2026_conference.tex`、`references.bib`、`iclr2026.bst`
- **确认**：克隆后 `ls iclr_template/iclr2026/` 看到上述文件即成功

**途径 2：Overleaf 模板（若 GitHub 拉不下来）**

1. 打开 https://www.overleaf.com/latex/templates/iclr-2026-template → "Open as Template"
2. 在 Overleaf 里 `Menu → Download → Source` 下载 zip
3. 解压到 `04_论文写作/iclr_template/`

**途径 3：自制最小 ICLR 风格（兜底，5 分钟）**

如果两个途径都不通，用 `article` 类 + 必要宏包自建，**保持视觉接近 ICLR**（双栏、10pt、booktabs 表格）：

```latex
% 04_论文写作/iclr_template/minimal_iclr.tex  —— 自制兜底模板
\documentclass[10pt,twocolumn]{article}
\usepackage[utf8]{inputenc}
\usepackage{times}            % ICLR 用 Times 系字体
\usepackage[margin=1in]{geometry}
\usepackage{booktabs}         % 三线表（F01 要求）
\usepackage{graphicx}
\usepackage{amsmath,amssymb}
\usepackage{hyperref}
\usepackage{caption}
\title{论文标题}
\author{团队名\\ 机构/参赛信息}
\begin{document}
\maketitle
% 正文结构：Abstract → Intro → Related Work → Method → Experiments → Discussion → Conclusion
\end{document}
```

> ⚠️ 无论哪条途径：**先用模板编译一次空文档确认 texlive 可用**（缺 texlive 会在阶段 1 就暴露，别拖到阶段 6）。

### 1.3 texlive 安装（服务器）

```bash
# 服务器：Ubuntu/Debian
sudo apt-get update && sudo apt-get install -y texlive-latex-base texlive-latex-recommended \
    texlive-latex-extra texlive-fonts-recommended texlive-bibtex-extra

# 编译验证（在 iclr_template 目录）
pdflatex iclr2026_conference.tex && bibtex iclr2026_conference && pdflatex iclr2026_conference.tex && pdflatex iclr2026_conference.tex
```

> 本地 Windows：装 MiKTeX（https://miktex.org）或 TeX Live；装完同样用上面四连编译验证。

## 2. 论文 7 段结构大纲（每篇论文的统一骨架）

> 写论文的**顺序**（FARS 附录 B Paper Writing Guidelines，原文顺序）：Methods → Experiments → Contributions → Conclusion → Introduction → Related Work → Abstract **最后写**。
> 下列 7 段是 F01 rail 校验的**硬结构**，缺一段 F01 会打回。

| # | 段落 | 标题（示例） | 内容要点 | F01 检测方式 |
|---|---|---|---|---|
| 1 | Abstract | `\begin{abstract}` | 150–250 词单段：context → problem → method → key result → implication；不引用 | 单词数区间 |
| 2 | Introduction | `\section{Introduction}` | 背景 → 缺口 → 一句话方案 → **贡献列表（itemize）** → 路线图 | 含 itemize 贡献列表 |
| 3 | Related Work | `\section{Related Work}` | 漏斗式：宽 → 窄 → 定位收尾"Unlike …, our approach…" | 章节存在 |
| 4 | Method | `\section{Method}` | 可复现：架构图 + 符号定义 + 算法描述 | 章节存在 + 含图 |
| 5 | Experiments | `\section{Experiments}` | Setup → Main results → Ablations → Analysis；**每个数字必须与 results.json 一致** | 章节存在 + F03 勾稽 |
| 6 | Discussion/Limitations | `\section{Discussion}` | 结果含义 + 诚实局限；负结果加分 | 章节存在 |
| 7 | Conclusion | `\section{Conclusion}` | 复述问题/方法 + 关键数字 + 未来工作；不引入新结果 | 章节存在 |

### 2.1 每段字数/图表目标（对标 Claude Code 高分画像）

| 指标 | 目标 | 备注 |
|---|---|---|
| 全文词数 | ≥ 4000 | F01 硬线 |
| 图 | 4–5 张 | `\includegraphics` 计数 |
| 表 | ≥ 6 张 | `\begin{table}` 计数 |
| 复杂度分析 | 必须含 | 检测 `O(` / `complexity` / `复杂度` / `Flops` |
| 参考文献 | 15–30 条 | 全部过 F04 核验 |
| 主内容页数 | 8–10 页（不含参考文献/附录）| 编译后人工核对 |

### 2.2 论文主题锚定（阶段 1 起就定，别中途换）

> 系统生成论文的主线 = 我们的比赛主线：**Rail-Augmented Harness for Rigorous and Self-Evolving Agentic Research**。
> 每篇"实验论文"（E1 的 5+5 篇、E2 的每轮 2 篇）可以是这个主线的子问题（如：rail 对捏造率的抑制、自演进闭环的 SAR 增益），但结构都走 7 段骨架。

### 3.2 核心原则

2. 统一风格：颜色序列、字号 ≥ 8pt、axis 标签完整、图例、`dpi=300`、PDF 格式
3. 每张图一个 `make_<fig_name>.py` 脚本（可复现），输出到 `paper/figures/`

| fig3_e2_sar | E2 Round 0/1/2 SAR 六维变化折线/雷达 | `05_评测与迭代/自演进实验/*.csv` | Experiments 3.2 |
| fig4_e3_bars | E3 基线对照柱状图（人类5.59/Claude5.45/FARS5.06/均值4.21/我们X）| 实验设计文档表 | Experiments 3.3 |
| fig5_e4_scatter | **成本-质量散点图**（x=单篇成本, y=SAR；FARS 右上，我们左下）| 资源日志 + SAR 记录 | Cost 章节（最有冲击力的一张）|

> fig5 是"全论文最有冲击力的一张图"（实验设计文档原话），阶段 6 前必须做出来。

### 3.4 表格生成要点（table_generator.py 行为）

- 读 `experiments/*/results.json` → 生成 `booktabs` 三线表（`\toprule/midrule/bottomrule`，无竖线）
- 最优值 `\textbf{}` 加粗 + `\uparrow/\downarrow` 标注方向
- caption 在表**上方**、自包含（"Best in bold. ↑ means higher is better."）
- 正文必须 `Table~\ref{tab:...}` 引用每张表

## 5. 论文定稿流程（阶段 6 执行，按顺序）

### 5.1 定稿步骤

1. **确定主叙事**（阶段 5 已决策）：T03（自演进）或 T04（严谨性）。本文件按 T03 写；若决策为 T04，把第 2 章改名为"以 F02/F03/F04 为核心的严谨性论证"，E2 移到 Future Work。
2. **数据核对**：论文所有数字对照 `05_评测与迭代/` 的记录（F03 自举校验，数字必须来自 results.json/CSV）。
3. **引用核验**：`python 03_技术实现/tools/citation_checker.py --file paper.tex --mode all`，所有引用 verified 才能冻结。
4. **F01 全过**：§4 的指标全 ✓。
5. **编译三连**：`pdflatex && bibtex && pdflatex && pdflatex`，无 error 无 undefined citation。
6. **人工通读**：叙事是否连贯、贡献列表是否清晰、负结果是否诚实——SAR 重"表述合理"。
7. **冻结**：复制到 `04_论文写作/论文_final/`，此后**不再改内容**，只允许排版修正。

### 5.2 复现包（阶段 6 做，决赛生命线）

在 `06_提交物/技术包/REPRODUCE.md` 写复现步骤，必须满足"**新环境照着跑一遍能复现论文**"：

```
# REPRODUCE.md 骨架
1. 环境：Python 3.12 + uv；`uv venv && uv pip install -r requirements.txt`（镜像注明）
2. 配置：复制 config/ 下 config.yaml，填入自己的 DEEPSEEK_API_KEY
3. 运行：`jiuwenswarm chat --skill research-pipeline --input <选题>`
4. 校验：`python tools/paper_metrics.py <论文>` + `python tools/citation_checker.py --file <论文>`
5. 复现结果：结果文件与提交论文数字一致（附核对脚本）
```

**自测要求**：在**另一台干净机器**（或新建 venv）按 REPRODUCE.md 完整跑一遍，有任何一步含糊就改文档。
