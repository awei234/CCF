## E1 严谨性增益（有 rail vs 无 rail）

### 目的
证明 F02/F03/F04 三个 rail 能显著降低三类违规（捏造 / 支撑不足 / 计划执行不匹配）并提升 SAR。

### 设计

| 组 | 配置 | 样本量 | 说明 |
|---|---|---|---|
| 对照组 | 科研 skill 无 rail | 5 篇 | 用同一 skill、同一模型、同一主题池 |
| 实验组 | 科研 skill + F02/F03/F04 | 5 篇 | 只多 rail 管控 |

**变量控制**：同一模型（deepseek-chat）、同一主题池、同一 skill 提示词、同 seed 策略。唯一变量 = rail。

### 指标

| 指标 | 测量方式 |
|---|---|
| 捏造率 | 抽检论文数字 vs results.json（F03 的未验证数字清单数 / 总数字）|
| 支撑不足率 | plan 声明实验数 vs 实际 results.json 数（勾稽）|
| 计划执行匹配率 | plan 中 baseline/ablation 是否都在论文中体现 |
| 假引用率 | F04 未通过引用数 / 总引用数 |
| SAR 总分 + 六维 | paperreview.ai |
| 单篇成本/时长 | 资源日志 |

### 预期结论（写论文时的说法）
- rail 组捏造率 → 近 0；对照组保留 baseline 数据（诚实报告，本身就是亮点）
- SAR 实验维度分差 ≥ 0.5
- 成本差异：rail 组因拦截返工略贵，但远小于 FARS 量级（可量化）

## E2 自演进闭环（Auto Harness 进化 rail）★核心实验

### 目的
证明系统能**自主评估自身不足 → 改进自己的 rail → 验证改进有效**（T03 的灵魂实验）。

### 设计：多轮进化（建议 3 轮，每轮 = 一次进化循环）

```
Round 0（基线）: 当前 rail 配置 → 生成 2 篇论文 → SAR 记录
      │
      ▼ 进化触发（喂给 Auto Harness 的 query）
Round 1: /auto-harness run --pipeline optimize_expert_harness \
         "分析最近 2 篇论文的 SAR 反馈（附 6 维分与修改建议）。
          评估科研严谨性扩展包的缺口，设计并实现改进
          （可新增/修改 rail、tool、skill），热加载生效。"
         → 生成/修改扩展 → verify_ext → 热加载激活
         → 用新 rail 配置生成 2 篇论文 → SAR 记录 → 对比 Round 0
      │
      ▼
Round 2: 同法再进化一轮（query 附 Round 1 的结果与 SAR）
         → 生成 2 篇论文 → SAR 记录
```

### 每轮记录（存 `05_评测与迭代/自演进实验/`）

| 记录项 | 内容 |
|---|---|
| Round 编号 | 0/1/2 |
| 进化前 rail 清单 | rail 名 + 关键参数 + hash |
| 进化 query | 喂给 Auto Harness 的原文 |
| 进化产物 | ExtensionDesign / 生成的扩展组件清单（rail/tool/skill）|
| verify_ext 结果 | 归因码（若有失败）|
| 进化后 rail 清单 | 与进化前 diff |
| 论文 SAR（2 篇均值）| 六维分 |
| 成本/时长 | 进化 run 的 Token 消耗 + 论文生成成本 |

### 论文呈现（关键叙事）

```
表：Round 0 → 1 → 2 的 SAR 六维变化（实验维度/写作维度预计上升）
图：自演进闭环架构图（assess → design → implement → verify → activate → 再评测）
案例：展示某轮进化"具体改了什么 rail、为什么、效果如何"
（例：Round 1 发现 F02 未强制新 baseline → 自动加规则 → 相关工作维度分提升）
```

### 失败预案（重要）

| 情形 | 处理 |
|---|---|
| Expert pipeline 跑不通 | 检查配置/环境（原理_02 §5）；先小 query 试跑；仍不行 → 降级 |
| 进化产物无效 | verify_ext 会拦；引导 Auto Harness 重试（fix_loop 机制）|
| 进化后 SAR 没涨 | 本身就是发现（诚实报告"该轮进化无增益 + 归因分析"）——SAR 对负结果友好 |
| **2 周内无法产出可用数据** | **切 T04 主叙事**：E2 数据用"人工改进 rail 的 A/B 对比"替代（E1 增强版），自演进写 Future Work |

### 备选（E2-lite，确定性更高的替代）
若 Auto Harness 全自动闭环不稳，可退化为"**半自动**"：人工给 agent 提供 SAR 反馈 + 让其设计 rail 改进（skill 引导），仍记录"反馈 → 改进 → 验证"数据。叙事上弱一些，但数据可靠。

## E3 基线对照

### 目的
把我们的分数放进参照系，证明超越 FARS 且接近人类录用线。

### 数据来源

| 基线 | 数值 | 来源 |
|---|---|---|
| 人类 ICLR 录用 | 5.59 | arXiv 2605.19156 Table 1 |
| Claude Code（最小 scaffold）| 5.45 | 同上 |

| 人类 ICLR 投稿均值 | 4.21 | FARS 官方博客 |
| **本项目（目标）** | **≥ 5.5** | 我们的 SAR 记录 |

### 论文呈现
- 柱状图对比 + 显著性说明（样本量小 → 诚实注明，附个体值）
- 强调成本对比（E4）：我们 $10 量级 vs FARS $1,040（100 倍差距）

## E4 成本

### 目的
证明"轻资产 + rail 增强"路线的成本优势。

### 指标（资源日志全程记录）

| 指标 | 目标 | FARS 对照 |
|---|---|---|
| 单篇 Token | ≤ 2000 万 | 1.14 亿 |
| 单篇成本 | ≤ $15 | $1,040 |
| 单篇时长 | ≤ 12h | ~2.3h/篇（他们流水线并行）|
| 进化 run 成本 | ≤ $10/次 | 无（FARS 不进化）|

### 论文呈现
- 成本-质量散点图（x=单篇成本, y=SAR）：FARS 在右上角（贵且分不高），我们在左下区域（便宜分高）——这是全论文最有冲击力的一张图。
