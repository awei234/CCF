## 1. 主题定义

从系统工程视角研究"全自动科研系统"的编排设计：流水线架构（Ideation→Planning→Experiment→Writing）、模块间协作机制（共享文件系统 vs 消息 vs 记忆）、并行调度与资源管理。

## 2. 为什么选

- **本质就是本赛题本身**：写"我们如何设计自动科研系统"本身就是论文内容
- FARS 的"科研装配线"就是经典范式，可对照、可改进
- 与 D05 混合架构直接对应（论文的 System Design 章节）

## 3. 论文角度

- 可作为 T03/T04 论文的 **System 章节**（介绍我们的流水线编排）
- 或独立成篇：对比不同编排策略（串行 vs 并行、单 Agent vs Team、共享文件系统 vs 记忆库）对论文质量的影响

## 4. 实验设计建议

| 实验 | 内容 |
|---|---|
| 编排对比 | 单 Agent 串行 vs Team 并行 vs 文件系统协作，测 SAR + 成本 |
| 调度 | 不同并行度下的资源利用 vs 论文质量 |

## 5. 风险与劣势

- 作为独立主题，容易写成"系统报告"而非"研究论文"，创新点需提炼
- 实验变量多，周期长

## 6. 与主线的关系

- 主要作为**系统设计章节素材**，不单独做主题
- 若 T03/T04 都不顺，可退化为系统型论文（但创新性维度会弱）
