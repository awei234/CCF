# 项目汇报：给老师的研究报告

> **题目**：用"机制"给科研 AI 上诚信保险——Rail-Augmented Harness for Rigorous and Self-Evolving Agentic Research
> **汇报人**：参赛团队
> **日期**：2026-08-12
> **材料来源**：`01_方向库/深度方案_T03_D05/`（7 篇方案 + 6 篇细化文档）+ FARS 评测论文（arXiv 2605.19156）等公开情报。报告中所有数字均可追溯；尚未完成的实验已如实标注"计划中"。

---

## 开场：我在参加什么项目

我参加的是一个 CCF 组织的开源 Agent 竞赛：要求基于 openJiuwen/JiuwenSwarm 开源框架开发一个"自动做科研、写论文"的 Agent，最终用客观评分系统 SAR（Stanford Agentic Reviewer）给生成的论文打分（满分 10，占初赛 40 分），并提交技术包与框架贡献。

一句话概括这个项目要回答的问题：

> **当 AI 能自己写论文时，我们怎么保证它写的是"真的"？并且，怎么让系统自己越写越好？**

下面按"问题 → 现状 → 原因 → 灵感 → 方案 → 创新 → 验证 → 结论"的顺序汇报。

---

## 1. 我们解决的是一个什么问题

科研 Agent 已能自动跑完"选题 → 做实验 → 写论文"全流程。2026 年基准研究 FARS（arXiv 2605.19156）用 **117 篇 AI 生成的论文**做了大规模实测，结论令人担忧：**AI 写的论文普遍在"造假"**，具体表现为三大失败模式——

| 失败模式 | 含义 | FARS 实测中招率 |
|---|---|---|
| **捏造结果** | 论文里的数字与实验文件对不上，甚至组件、引用都是编的 | 最高 **77%** |
| **实验支撑不足** | 一个数据集当多个用、只跑单种子、实验写得像小试 | **49.6%** |
| **计划与执行不匹配** | 计划里的 baseline 没实现、消融没跑，论文却照写 | **23.9%** |

这不是"文笔不好"的小问题，而是**学术诚信层面的结构性问题**：生成式模型"编数字、编引用"的概率性行为，直接动摇了论文作为科学产物的可信根基。

除此之外还有一个隐蔽问题：**现在的科研 Agent 都是"一次性"的**——系统跑完一篇论文就结束了，不知道自己哪里被扣分，更不会改进自己。

所以问题收敛为两个：

1. **如何用机制（而不是靠模型自觉）保证科研 Agent 的"计划—执行—报告"一致、数字与引用真实？**
2. **如何让系统根据外部评测反馈，自动改进自身，越写越好？**

## 2. 现在主流的方法是怎么解决的（三类）

调研了当前全部主流路线，可归纳为三类：

### 第一类：Prompt 工程派（把规矩写进提示词）
做法：给 agent 一份很详细的研究指南，如 FARS 的"四阶段指南"（选题、规划、实验、写作各一份 prompt），要求它"不许捏造、每个数字都要有出处"。
**缺点**：提示词本质是"道德建议"，模型可以不听。FARS 的实测结果就是铁证——三款顶级 Agent 都拿了这份指南，捏造率照样最高 77%。**规则写得再好，不执行等于零。**

### 第二类：多 Agent 评审派（用 AI 审 AI）
做法：让多个 Agent 互相评审/自我修正（如 ResearchAgent、Agent Laboratory、Self-Refine、SAR 评审）。
**缺点**：评审者也是 LLM，同样会幻觉，"用另一个可能造假的裁判去裁判造假"；而且评审与实验事实分离——评审只读论文文本，无法核对实验结果文件；成本也高（FARS 单篇 $1,040）。

### 第三类：代码沙箱执行派（强制跑代码）
做法：让 agent 必须通过真实代码执行实验，如 Karpathy 的 Auto-Research（反复迭代一个 train.py）、MLR-Bench（模块化流水线）。
**缺点**：只能覆盖"能跑代码"的窄场景；**论文写作环节的数字与引用依然不受控**——代码跑出 87.3，写论文时照样可能写成 97.3；对"规划—执行—报告"的一致性也没有机制保证。

**三类方法的共同盲区**：都把"诚信"寄托在**模型层**（更好的提示词、更好的评审模型），而忽略了**系统层**——没有任何一类方法在 Agent 的运行机制里装上"物理上写不进去就过不去"的闸门。

## 3. 背后的真正原因是什么

为什么三大失败模式如此普遍？根因有两个：

**根因一：幻觉是生成式模型的物理属性，不是可以靠"讲道理"消除的。**
LLM 的生成机制是"概率续写"——它追求的是"这段文字在统计上像真的"，而不是"与外部事实一致"。训练时只能对齐到"通用场景的诚实"，无法覆盖你的实验数据、你的参考文献这些具体事实。所以当模型需要填一个具体数字时，它天然倾向于"编一个合理的"，除非有一个外部机制拦住它。**这就是为什么"提示词叫它别造假"没用——那是给模型的道德建议，不是系统的物理约束。**

**根因二：主流研究都在"模型层"用力，忽略了"系统层"。**
Agent = 模型（大脑）+ Harness（工程控制层：任务循环、工具、上下文、校验、停止条件）。FARS 的失败恰恰发生在 Harness 该管而没管的地方：**实验规划没有强制校验、论文数字没有出处检查、引用没有真实性核验**。整个学术界在"让模型更聪明"上投入巨大，在"让系统更守纪律"上几乎空白——这就是我们的机会窗口。

## 4. 我如何突破原有局限：从科学角度找到的灵感

跳出"AI 圈"看，三个成熟领域的智慧给了我们直接启发：

1. **工业质量管理（质量门禁）**：汽车、芯片工厂从不指望工人"自觉"，而是在产线上设**质检工位**——不合格品物理上流不到下一道工序。科研 Agent 缺的就是这道门禁。
2. **软件工程（CI/CD 与代码评审）**：代码不是靠"开发者保证没 bug"合入的，而是靠 **CI 门禁**（lint、测试必须全过才能合入）。"纪律 = 机制，而非自觉"是工程界的常识。
3. **控制论与进化论（闭环反馈）**：一个系统要变好，必须有"评估 → 差距 → 改进 → 再评估"的闭环（类比 RLHF，但改的是系统结构，而不是模型权重）。

由此形成本项目的核心命题：

> **把"诚信"从模型的道德属性，改造成系统的结构属性；把"越写越好"从人工调参，改造成系统的自动闭环。**

## 5. 我设计的新思路与新方法（总览）

基于"Agent = Model + Harness"的哲学，**完全不动模型，只改造 Harness 层**（与模型解耦，换任何模型都成立），搭建四层系统：

```
第4层 演进层：Auto Harness —— 系统自评估→自改进→再验证（闭环）
第3层 管控层：自定义 Rail —— 科研纪律的"质检工位"（机制性诚信）
第2层 流程层：科研 Skill —— 四阶段流水线手册（选题→规划→实验→写作）
第1层 底座：JiuwenSwarm + DeepSeek
层间数据契约：plan.json → experiments/*/results.json → paper/paper.tex
```

一句话概括新方法：

> **用可执行的 Rail（生命周期钩子）把科研纪律变成"物理门禁"，用勾稽链保证"计划—执行—报告"三方一致，再用 Auto Harness 让系统根据评测分数自动改进自己的门禁——实现"机制性诚信 + 自演进"。**

## 6. 新思路具体是什么

**思路一：机制性诚信（Rail 门禁，而不是提示词建议）。**
JiuwenSwarm 框架提供 Rail 机制——在 Agent 生命周期的关键节点（工具调用前、模型输出后、任务轮次间）插入自定义校验逻辑。我们设计了四个科研 Rail，把"纪律"变成"写不进去就过不去"：

| Rail | 管什么 | 对应 FARS 病灶 |
|---|---|---|
| F02 实验规划 | plan.json 不达标（实验<3、baseline<2、无消融、种子<3）直接打回 | 支撑不足 49.6% |
| F03 结果一致 | 论文每个数字必须能在 results.json 找到出处 | 捏造结果 77% |
| F04 引用核验 | 每个 \cite 必须命中真实文献池/在线可查 | 假引用 72% |
| F01 写作质量 | 词数≥4000、图≥4、表≥6、7 段结构、复杂度分析 | 写作下限 |

**思路二：勾稽链（计划—执行—报告三方一致）。**
核心是一个数据契约：**plan.json 声明什么 → experiments/ 必须产出什么 → paper.tex 只能引用 results.json 里的什么**。三层之间互相勾稽，任何一环造假都会在机制上被卡住。这是对 FARS"计划执行不匹配 23.9%"的直接解法。

**思路三：Harness 层"后训练"（自演进闭环）。**
类比 RLHF 是改权重，我们让系统**改自己的 Harness**：把第三方评测 SAR 的 6 维分数 + 修改建议喂给框架自带的 Auto Harness → 它自主评估"科研严谨性扩展包缺什么" → 设计/实现新的 Rail → 热加载生效（无需重启）→ 重新生成论文 → 再评测对比。系统从此会"自己变强"。

## 7. 新方法具体怎么做

**第 1 层底座**：JiuwenSwarm 开源框架 + DeepSeek（OpenAI 兼容接口接入），只做配置，不改模型。

**第 2 层流程**：自研 `research-pipeline` Skill（框架目前没有科研类 skill，这是空白），把 FARS 附录 B 的四阶段指南改编成中文操作手册，规定每阶段必须产出固定文件（proposal.md / idea.json / plan.json / results.json / paper.tex）。

**第 3 层管控**：四个 Rail 基于框架的 `DeepAgentRail` 基类开发，全部走真实钩子：
- F02 在 `before_tool_call` 拦截 plan.json 的写入，用 `_skip_tool` 协议拒绝不合规内容并返回修正清单
- F03 在 paper.tex 每次写入后提取全部数字，与 results.json 做精确匹配 + 均值推导匹配，未验证数字注入系统提示引导修正
- F04 用 `references/` 文献池优先匹配，池外引用走 arXiv/Semantic Scholar 双通道在线核验（容错规则：网络失败绝不误杀）
- F01 用 LaTeX 解析器检查词数/图表/复杂度/结构，缺口清单注入提示词引导补齐

开发期用框架的**热加载机制**（rail 放入工作区 extensions 目录即可生效，改完即用、无需重启），稳定后移植为正式声明式装配。

**第 4 层演进**：配置 Auto Harness（git 身份、预算红线 $10/次），用 `optimize_expert_harness` pipeline 跑"评估→设计→实现→热加载→再验证"闭环；用 `optimize_meta_harness` pipeline 把改进提成 PR 给 openJiuwen 开源仓库，作为合规的框架贡献交付物。

## 8. 创新点体现在哪里

对比赛评分六维（原创性 25% / 重要性 20% / 方法 20% / 严谨性 15% / 清晰度 10% / 相关 10%），创新点逐条对应：

| 创新点 | 与现有工作的差异 | 对应评分维度 |
|---|---|---|
| **① 机制性诚信**：用 Rail 门禁替代提示词建议 | 三类主流方法都在"模型层"用力，我们在"系统层"上闸门；FARS 的三大失败模式被从机制上堵死 | 原创性 + 严谨性 |
| **② 勾稽链数据契约**：plan→results→paper 三方一致 | 评审派评审与事实分离、工具派只控实验不控写作——我们全链路闭环 | 严谨性 + 方法 |
| **③ Harness 层自演进**：系统根据评测反馈改自己的 Rail | 现有科研 Agent（含 FARS）全部是静态一次性；把"后训练"从改权重扩展到改系统 | 原创性 + 重要性 |
| **④ 成本优势**：单篇 ≤$15 vs FARS $1,040（100 倍）| 不靠烧 Token 试错，靠机制拦截无效路径 | 应用前景/重要性 |

一句话：**别人在教模型"别撒谎"，我们在给系统装"测谎仪 + 质检线 + 自我教练"。**

## 9. 验证方法好不好：四组严格实验

所有实验数据来自系统真实运行，每篇论文留痕（config 版本 hash、results.json、SAR 记录）保证可复现；SAR 是斯坦福第三方评测，非自评。

**E1 严谨性增益实验（核心证据，W3 执行）**
对照组：科研 Skill 无 Rail，生成 5 篇；实验组：Skill + F02/F03/F04，生成 5 篇。严格变量控制：同模型、同主题池、同 seed，唯一变量是 Rail。
指标：**捏造率**（未验证数字/总数字）、**支撑不足率**、**计划执行匹配率**、**假引用率**、SAR 六维。
预期结论：实验组捏造率趋近于 0，SAR 实验维度分差 ≥0.5——直接证明"机制性诚信"有效。

**E2 自演进闭环实验（灵魂证据，W5 执行）**
3 轮进化：基线 2 篇 → 把 SAR 反馈喂给 Auto Harness → 它自主改进 Rail → 热加载 → 再生成 2 篇 → 对比 SAR。每轮记录：进化 query、rail diff、归因码、SAR 变化、成本。
即使某轮 SAR 没涨，也如实报告并做归因分析（负结果本身就是发现）。

**E3 基线对照**
把我们放进参照系：人类 ICLR 录用 5.59 / Claude Code 5.45 / FARS 5.06 / 人类投稿均值 4.21；**我们的目标 ≥5.5**（达到 Claude Code 水平、超过 FARS 0.4 分以上）。

**E4 成本对照**
单篇 Token ≤2000 万（FARS 1.14 亿）、单篇成本 ≤$15（FARS $1,040）、单篇时长 ≤12h。成本-质量散点图：FARS 在"贵且分不高"的右上角，我们在"便宜且分高"的左下角——这是全论文最有冲击力的一张图。

**目前已完成的事实**（如实汇报，不夸大）：
- 服务器环境全部跑通（DeepSeek 调用、Rail 基类导入、拦截协议、priority 规则均已实测验证）
- 四层架构、四个 Rail、Skill、Auto Harness 配置方案已完成到"可直接编码"的规格
- E1/E2 实验数据按计划在 W3/W5 产出——**尚未伪造任何结果**，这也正是我们的方案要防的事

## 10. 结论

这个项目的意义分三层：

1. **对比赛**：SAR 评分 40 分，原创性 25% 与严谨性 15% 是我们的主攻方向——机制性诚信 + 自演进直接命中最高权重维度；框架贡献（PR）满足硬性要求。
2. **对学术**：我们提出并实现了一个全新视角——**把科研诚信从模型道德改造为系统机制，把 Agent 的自演进从改权重扩展到改 Harness**。FARS 的实测数据（三大失败模式）恰好是我们方案的对照靶子。
3. **对工程**：全部基于开源框架，成果可贡献回社区，他人可复现、可复用。

**给老师的一句话总结**：
> 现在的主流是"教 AI 诚实"，我们的做法是"让 AI 想不诚实都不行"，并且让这套机制能自己进化——这就是本项目的核心创新。
